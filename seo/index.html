Сделано локально

  • 19 новых страниц; общая навигация, ссылки по материалу и типу объекта.
  • Уникальные Title, Description и H1; хлебные крошки с BreadcrumbList; взаимные ссылки.
  • Канонические адреса и sitemap.xml под текущий адрес GitHub Pages: https://romariobro.github.io/orbita/.
  • Статический HTML без зависимости от JavaScript; прямые ссылки звонка и почты.

P0 — до публикации новых страниц

  1. Владелец: подтвердить фактический состав услуг и территорию работы; проверить тексты, контакты и сведения о документах.
  2. Владелец + инженер: предоставить сканы лицензий, сертификатов, примеры протоколов; проверить технические формулировки статей. Не публиковать номера и аккредитацию без документов.
  3. SEO + владелец: выбрать основной домен: текущий GitHub Pages или orbita-p.ru. При смене домена заменить BASE, canonical и sitemap для всех страниц. Не индексировать две одинаковые копии как самостоятельные сайты.
  4. SEO: выгрузить Wordstat по Пензе и области, проверить точные формулировки, коммерческую выдачу и сезонность. Расширить синонимы, удалить нерелевантное, уточнить P1/P2. Не создавать страницы под нулевой спрос без пользовательской ценности.
  5. Разработчик: после согласования пересобрать релиз из актуальных страниц и ассетов. Старый github-pages-release пока не содержит новых страниц.

P1 — запуск и измерение

  1. Подключить Яндекс Вебмастер и Google Search Console к выбранному адресу, подтвердить права и отправить sitemap.xml.
  2. Настроить правила robots.txt на корне основного хоста. На проектном GitHub Pages файл /orbita/robots.txt не управляет robots.txt домена; не считать его полноценной настройкой индексации.
  3. Подключить Метрику и цели кликов по телефону и почте. Клик не считать состоявшейся заявкой: вести отдельный учёт обращений и их качества.
  4. Заполнить карточку компании в Яндекс Бизнесе: единые название, адрес, телефон, фотографии и часы работы.
  5. Проверить опубликованные URL: HTTP 200, изображения, мобильное отображение, canonical, sitemap, отсутствие запрета индексации. Проверить несуществующие URL на настоящий 404.
  6. Снять показатели скорости и Core Web Vitals на опубликованном сайте; оптимизировать изображения и размеры загрузки по результатам, а не по догадкам.

P2 — развитие содержания

  1. Подготовить 3–5 реальных кейсов: объект, исходная задача, объём, сроки, применённая система, фото и подтверждённый результат. Затем создать отдельные страницы /proekty/имя-объекта/.
  2. Добавить подтверждённые примеры смет и условия цены. Не копировать цены конкурентов.
  3. Уточнить сведения о лаборатории: собственная или привлечённая, область деятельности, документы. Только после этого создавать самостоятельную коммерческую страницу.
  4. Развивать статьи по вопросам из реальных обращений; технические тексты проверяет профильный специалист.
  5. Через 4–8 недель после индексации оценить показы, запросы, CTR, обращения и качество лидов. Корректировать заголовки и содержание по данным, без обещаний позиций.

Что не делаем

Не размножаем одинаковые страницы по городам и пределам огнестойкости. Не заявляем неподтверждённые цены, сертификаты, объёмы и сроки. Страницы кейсов пока не созданы: исходные фото не подтверждают результат конкретного проекта.
